# 数据库迁移与回退

使用既有 GORM AutoMigrate 和 schema_migrations 版本记录，不再增加迁移引擎。启动通过 MySQL advisory lock 串行迁移，状态区分 running/completed，仅已完成版本可以跳过。当前显式迁移到版本 4，代码实现为准。

## 变更规则

先加可空字段/新表，再回填和加约束；回填可重试、有边界，并添加真实 MySQL 的失败恢复/二次启动测试。不要关闭外键校验掩盖错误。设备未分组用 NULL，保留群组删除 ON DELETE SET NULL。MySQL DDL 可能隐式提交，不能认为 GORM 迁移可整体事务回滚。旧 wall-clock DATETIME 不应在不知道原时区时整体平移。

## 升级流程

1. 停止入口写入、后台播报和中心，记录旧版本、镜像摘要、配置、密钥及迁移版本。
2. 一致性备份数据库，并同步备份对象/本地存储、配置和密钥，在隔离环境做恢复演练。
3. 数据库副本先运行新版本，确认迁移、空群组设备、登录/撤销、UDP/WS、音频和文件访问。
4. 单个中心执行生产迁移，确认没有 running 遗留，再恢复流量。不要让多个不同版本同时改库。

## 回退

仅新增且已验证旧程序兼容的变更，可停新程序、切换旧二进制并保留数据库。清洗/删除/约束或语义变化需要停写，将升级前备份恢复到新库，用配套旧配置、密钥和对象快照验证后再切入口。升级后新写入不会自动并回旧快照，恢复前决定需要保留的数据。

不要手动把失败迁移改为 completed。检查部分落地 DDL、保留备份和日志，修复原因后重试幂等迁移。`go run ./tools/integration -only migration-recovery,authentication` 验证迁移恢复及重复启动，不能代替生产数据副本演练。
