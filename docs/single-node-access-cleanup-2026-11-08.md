# 单节点设备接入与旧边缘架构清理方案

日期：2026-11-08。实施分支：`dev`；`edge` 分支保留原状。

## 设计目标

每个独立主站只维护一个自身的设备接入点。管理员在后台设置节点 ID、节点 IP／域名及对外 UDP 端口。设备只配置 HTTP API 地址和原有设备认证信息，通过 API 查询实际接入地址，再建立 UDP 连接。节点地址变化时更新后台，设备重新查询后使用新地址。

站间互联（中心互联）继续保留：各主站独立管理用户、设备和群组，通过邀请准入、群组映射和双方权限交换音频。本方案删除的是一个中心管理多个边缘节点的旧架构。

## 后台接入点配置

- 核心字段：节点 ID、节点 IP／地址（支持域名）、节点 UDP 端口。
- 不设置发布开关，发现接口默认提供本站入口。未填写地址时使用设备查询 HTTP API 的主机名，未填写端口时使用本机 UDP 监听端口；公网映射地址可单独覆盖。
- 节点 ID 是稳定的公开标识；IP 或端口变化不自动改变 ID。中心互联的站点身份独立保持稳定。
- 显示名称使用站点名称，删除重复名称、地区、网络标签、优先级和候选节点排序。
- 发现凭据有效期和短缓存使用内部默认策略，保留认证及限流能力。
- API 公布对外可达地址，允许与 NAT 后的本机监听地址不同。

## 设备流程与接口

1. 设备访问配置的 HTTP API。
2. 使用设备凭据获取发现凭证，调用接入点查询接口。
3. 获取节点 ID、IP／地址、UDP 端口，连接并完成设备认证。
4. 启动、缓存过期或连接持续失败时重新查询，并通过退避策略重连。

沿用 `POST /api/device/access-points/token` 和 `GET /api/access-points`。保留既有 `items` 响应包装，始终提供一个本机入口；旧发布开关被忽略。旧设备依赖的响应字段可保留无调度意义的兼容默认值。后台保存后立即清除服务端配置缓存，设备端最长按公告的短缓存重新查询。

服务端不保证未实现发现／重查逻辑的旧固件自动切换；模拟设备测试覆盖服务端查询及重新连接流程。

## 清理范围

- 移除边缘节点管理 API、前端页面、服务、类型及注册／认证／凭据轮换／吊销／断开逻辑。
- 移除旧边缘控制连接、心跳、设备授权、上下行转发、边缘路由投影、远程配置同步和恢复票据。
- 移除边缘专属配置、定时任务、缓存、指标、日志类别以及设备跨节点归属／迁移逻辑。
- 保留本机 UDP、WebSocket、幽灵多会话、普通设备配置同步、录音和通信记录。
- 将中心互联从旧边缘共用组件中拆出，保留 HTTP 准入、共享主 UDP 音频、邀请、群组映射、收发权限、虚拟服务器设备、状态及重连。
- 自动播报继续局限于来源群组，不因本地群组互联或站间互联传播。
- 清理仅供旧多边缘功能使用的数据库字段和索引，使用版本化迁移；业务数据和中心互联数据保持完整。
- 迁移已有节点公开 ID、UDP 地址和端口；废弃配置项被忽略，不恢复边缘运行时。
- 更新首页结构图、配置示例、使用说明、数据字典、路由索引和生成的 OpenAPI；主线文档不再引导部署旧边缘架构。

## 实施记录

### 已实现行为

后台接入点配置仅保留 `node_id`、`udp_host`、`udp_port` 三个字段，无发布开关。默认节点 ID 为 `center`；地址未配置时按每次请求的 HTTP Host 解析，端口未配置时采用 `System.Port`。按请求生成默认地址时复制配置，不把某次请求的 Host 写入共享缓存。显式填写的公网／NAT 地址和端口优先，保存后立即清除配置缓存。发现凭据有效期固定为 300 秒，发现结果缓存 5 秒。

旧边缘运行时、控制协议、转发、注册凭据、入口归属索引及管理接口／页面已删除。本站会话改由本地仲裁器管理，独立站间互联保留 HTTP 准入、共享主 UDP 音频、双方权限及持久化会话恢复。普通设备配置上报／同步、幽灵多会话和录音继续保留。激活后请求取消时会撤销未提交的会话授权，避免留下孤立授权。

版本 5 数据库迁移把旧中心公开 ID、UDP 地址和端口转成三个本站配置键，不覆盖已经存在的新值；旧发布状态及其余废弃发现项被清除。迁移幂等移除设备／中继入口归属、群组主从、服务器边缘凭据和投影字段，保留业务行与独立站间会话。原 `servers` 基础目录行只作为历史数据保留，应用不再使用。旧 YAML 边缘选项被忽略。

实际测试中还修复了配置批量保存跳过空字符串的问题：清空公网地址现在能正确保存，并恢复按 HTTP Host 发现本站地址；重复迁移不会把旧公网地址重新写回。
