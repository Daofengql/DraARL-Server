# 错误码与状态码

## HTTP 状态码

### 标准状态码

| 状态码 | 说明 | 使用场景 |
|--------|------|----------|
| 200 | OK | 请求成功 |
| 201 | Created | 资源创建成功 |
| 400 | Bad Request | 请求参数错误 |
| 401 | Unauthorized | 未认证或token无效 |
| 403 | Forbidden | 无权限访问 |
| 404 | Not Found | 资源不存在 |
| 409 | Conflict | 资源冲突（如重复绑定） |
| 422 | Unprocessable Entity | 请求格式正确但语义错误 |
| 429 | Too Many Requests | 请求频率超限 |
| 500 | Internal Server Error | 服务器内部错误 |

### 统一响应格式

```json
{
  "code": 200,
  "message": "成功",
  "data": {}
}
```

### 错误响应格式

```json
{
  "code": 400,
  "message": "请求参数错误",
  "data": {
    "field": "username",
    "detail": "用户名长度不能少于3个字符"
  }
}
```

## JWT 认证响应状态码

### Type=1 (JWTAuth) DATA[0] 状态码

| 值 | 说明 |
|----|------|
| 0 | 认证成功 |
| 1 | Token无效或过期 |
| 2 | 用户不存在 |
| 3 | 用户已禁用 |
| 4 | 用户未审核 |
| 5 | 无效设备型号（非101-104） |

### 响应格式

```
DATA[0] = 状态码 (0=成功, 非0=失败)
DATA[1:] = 错误消息 (UTF-8, 失败时)
```

UDP 幽灵认证成功以 `DATA[0] = 0` 开头，后续 DATA 为版本化 JSON，Reserved 同时携带 `session_tag`：

```json
{
  "version": 1,
  "session_id": "7fbbbd37-9207-4df2-b79d-e400e0a09fd0",
  "session_tag": 270544961,
  "client_instance_id": "41a065d7-f9e1-4785-bbcb-22c3ca8784ad",
  "tx_group_id": 1001,
  "rx_group_ids": [1001, 1002]
}
```

旧 raw-JWT 或无版本化 JSON 的客户端返回 `ghost_protocol_upgrade_required`；缺少必需能力返回 `ghost_capabilities_required`。账号达到会话上限或 Session 注册失败时也复用状态 `1`，并在 `DATA[1:]` 返回机器可读原因；达到上限时格式为 `ghost_session_limit active=<当前数> limit=<上限>`。客户端不得把所有状态 `1` 都显示成“Token 过期”。

## 幽灵 Session 与路由错误

`PUT /api/radio/sessions/:session_id/routing` 的响应除 HTTP `code` 外，还可能返回稳定的 `error` 标识：

| HTTP | `error` | 含义 | 客户端处理 |
|---:|---|---|---|
| 400 | `invalid_routing` | 发送频道无效，或接收集合含非正整数 | 修正请求后重试 |
| 403 | `group_forbidden` | 至少一个频道当前不可访问 | 移除无权限频道 |
| 404 | `session_not_found` | Session 不存在或不属于当前账号 | 刷新会话列表并重新连接 |
| 404 | `group_not_found` | 至少一个频道不存在 | 刷新频道列表 |
| 422 | `subscription_limit` | 规范化后超过 `GhostSessions.MaxSubscriptionsPerSession` | 根据响应中的 `requested` 与 `limit` 减少接收频道 |
| 500 | `routing_update_failed` | 持久化或运行时投影失败 | 保留旧路由并稍后重试 |

`DELETE /api/radio/sessions/:session_id` 对不存在、已断开或不属于当前账号的 Session 返回 `404 session_not_found`。路由更新是原子的：失败时服务端应继续使用更新前的完整路由。

## WebSocket 握手与关闭

协议升级前可能返回以下纯文本 HTTP 错误：

| HTTP | 响应文本 | 含义 |
|---:|---|---|
| 401 | `token_required` | 缺少 `ws_token` Cookie |
| 401 | `invalid_token` / `user_not_found` / `user_disabled` / `user_not_approved` | 账号认证失败 |
| 401 | `ghost_protocol_upgrade_required` | 未提供现代幽灵实例协议参数 |
| 401 | `invalid_client_instance_id` | 实例 ID 不是有效 UUID |
| 401 | `ghost_capabilities_required` | 缺少 `multi_receive_v1` 或 `source_group_v1` |
| 401 | `client_preference_unavailable` | 无法加载实例路由偏好 |

Session 注册在 WebSocket 升级后失败时，服务端使用标准关闭码 `1008`，关闭原因包含具体注册错误，例如会话上限。客户端应展示原因并停止无休止重连。

## 心跳响应状态码

### Type=2 (Heartbeat) 响应

普通设备心跳认证成功后，服务器会在响应中填充 CallSign。

**成功响应**:
```
Header:
  CallSign: "BG1AAA" (服务器填充)
  
DATA: 原样返回设备发送的DATA
```

**失败响应**:
服务器直接丢弃心跳包，不返回响应。

## 设备认证失败处理

### 阶梯封禁机制

```
失败次数    封禁时长    封禁Key
1-3        无          -
4          10秒        IP + Username
5          30秒        IP + Username
6          60秒        IP + Username
7+         300秒       IP + Username
```

### 封禁响应

被封禁的设备发送心跳包时，服务器直接丢弃，不返回响应。

设备可通过以下方式判断是否被封禁：
1. 发送心跳后长时间无响应
2. 尝试其他用户名（如果封禁是基于IP+Username）

## HTTP 限流响应

### 429 Too Many Requests

```json
{
  "code": 429,
  "message": "请求过于频繁，请稍后重试",
  "data": {
    "retry_after": 9
  }
}
```

### 限流规则

| 接口 | 限流策略 |
|------|----------|
| `/api/auth/login` | IP每秒5次 |
| `/api/auth/send-code` | IP每分钟2次 |
| `/api/auth/register` | IP每小时5次 |
| `/api/device/pre-check` | IP每秒1次，MAC每分钟5次 |
| `/api/device/request-code` | IP每10秒1次，MAC每分钟1次 |
| `/api/device/confirm-bind` | MAC每5秒1次 |
| `/api/device/bind` | 用户每分钟5次 |
| `/api/device/submit-config` | 用户每分钟10次 |
| `/api/public/relays` | IP每分钟10次 |
| `/api/public/client-resources/manifest` 与 `/api/public/client-resources/artifacts/:artifact_id/download` | 共享 IP 每分钟30次 |

## 错误处理最佳实践

### 客户端错误处理

```javascript
async function apiRequest(url, options) {
  try {
    const response = await fetch(url, options);
    const data = await response.json();

    if (response.ok) {
      return data;
    }

    switch (response.status) {
      case 401:
        // Token过期，尝试刷新
        const refreshed = await refreshToken();
        if (refreshed) {
          // 重试原请求
          return apiRequest(url, options);
        }
        // 刷新失败，跳转登录
        window.location.href = '/login';
        break;

      case 403:
        showToast('无权限访问', 'error');
        break;

      case 404:
        showToast('资源不存在', 'error');
        break;

      case 429:
        const retryAfter = data.data?.retry_after || 5;
        showToast(`请求过于频繁，${retryAfter}秒后重试`, 'warning');
        await sleep(retryAfter * 1000);
        return apiRequest(url, options);

      default:
        showToast(data.message || '请求失败', 'error');
    }

    throw new Error(data.message);
  } catch (error) {
    if (error.name === 'TypeError') {
      showToast('网络错误，请检查连接', 'error');
    }
    throw error;
  }
}
```

### WebSocket 错误处理

```javascript
ws.onerror = (error) => {
  console.error('WebSocket error:', error);
  showToast('连接错误', 'error');
};

ws.onclose = (event) => {
  switch (event.code) {
    case 4001:
      showToast('认证失败', 'error');
      break;
    case 1008:
      showToast(event.reason || '当前会话不符合服务端策略', 'warning');
      break;
    case 1006:
      showToast('连接异常断开，正在重连...', 'info');
      reconnect();
      break;
  }
};
```
