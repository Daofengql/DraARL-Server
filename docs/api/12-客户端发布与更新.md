# 12. 客户端发布与更新

客户端发布与设备固件发布使用独立的数据模型。管理员先创建草稿，再为每个操作系统和架构完成一个安装包对象，最后发布。已发布版本不可覆盖；问题版本必须撤回并发布新版本。

Android 架构严格匹配：`armv7`（或 `armeabi-v7a`）只会得到 `armeabi-v7a` 包；`arm64`（或 `arm64-v8a`、`aarch64`）只会得到 `arm64-v8a` 包。只有管理员显式上传 `universal` 包时才允许回退，绝不会把 arm64 包返回给 armv7 设备。同一版本同时存在精确 ABI 与 universal 时优先精确 ABI；较新版本只有 universal 时仍可正常升级。

## 管理接口

所有管理接口均需要管理员 Bearer Token。

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/client-releases` | 分页列表，支持 `app_id`、`version`、`channel`、`status`、`platform`、`arch` 筛选。 |
| POST | `/api/client-releases` | 创建草稿。 |
| GET | `/api/client-releases/:id` | 获取草稿/发布详情与平台矩阵。 |
| POST | `/api/client-releases/:id/artifacts/complete` | 校验已直传的对象并添加安装包。 |
| POST | `/api/client-releases/:id/publish` | 发布至少包含一个完整 artifact 的草稿。 |
| POST | `/api/client-releases/:id/withdraw` | 撤回已发布版本。 |
| DELETE | `/api/client-releases/:id` | 仅删除草稿及其安装包对象。 |

### 创建草稿

```http
POST /api/client-releases
Content-Type: application/json

{
  "app_id": "draarl-client",
  "version": "1.2.0",
  "channel": "beta",
  "title": "音频稳定性更新",
  "changelog": "修复音频连接问题",
  "force_update": false,
  "min_supported_version": "1.0.0"
}
```

`version`、`min_supported_version` 采用严格 SemVer 2.0.0 格式，支持预发布和构建元数据，例如 `1.2.0-beta.1+build.42`；不接受前导 `v`、数字段前导零或下划线。`min_supported_version` 不得高于本次发布版本。频道首期只允许 `stable` 与 `beta`。

### 上传 artifact

先调用已有的 `POST /api/storage/presign-put`：

```json
{
  "file_type": "client_package",
  "file_name": "draarl-1.2.0-arm64-v8a.apk",
  "size": 52428800,
  "content_type": "application/vnd.android.package-archive"
}
```

浏览器将文件 `PUT` 到响应的 `upload_url`，之后调用 complete。服务端会校验管理员、upload token、staging 前缀、实际对象大小、扩展名和 Content-Type，提升为不可变 final 对象后从 final key 重算 SHA-256 并复核大小。前端提交的哈希不被信任。

```http
POST /api/client-releases/42/artifacts/complete
Content-Type: application/json

{
  "platform": "android",
  "arch": "arm64",
  "package_type": "apk",
  "build_number": "120",
  "min_android_api": 26,
  "file_name": "draarl-1.2.0-arm64-v8a.apk",
  "object_key": "staging/client_package/7/2026/07/…apk",
  "upload_token": "…",
  "signature": "可选签名元数据",
  "signature_algorithm": "ed25519"
}
```

支持的组合：

| 平台 | 架构 | 包类型 |
|---|---|---|
| `android` | `armv7`、`arm64`、`universal` | `apk` |
| `windows` | `x86_64`、`universal` | `exe`、`msix` |
| `macos` | `arm64`、`x86_64`、`universal` | `dmg`、`pkg` |
| `ios` | `arm64`、`universal`（`app_store` 仅 `universal`） | `app_store`、`ipa` |

`min_android_api` 只能用于 Android artifact；其他平台如需限制系统版本，应使用 `min_os_version`。`android_abi` 同样只允许 Android 使用，并且必须与归一化后的 `arch` 一致。`app_store` 必须使用 `universal` 架构，不上传 IPA，而是在 complete 请求提供 HTTPS `external_url`（App Store 或 TestFlight 地址）；`ipa` 才可使用 `arm64` 或 `universal`，其他包类型不能提供 `external_url`。正式 APK 应使用应用签名，Windows 包应有 Authenticode 签名，macOS 包应完成签名和公证。

`signature` 与 `signature_algorithm` 是一组可选的额外校验元数据：可以都不填写，但不能只填写其中一个。客户端若收到这两个字段，应在 SHA-256 校验通过后按指定算法验证签名。

## 公共更新查询

```http
GET /api/public/client/latest?app_id=draarl-client&platform=android&arch=arm64&current_version=1.1.0&channel=stable&android_api=26
```

| 参数 | 说明 |
|---|---|
| `app_id` | 可选，默认 `draarl-client`。 |
| `platform` | 必填：`android`、`windows`、`macos`、`ios`。 |
| `arch` | Android 必填；其他平台省略时按 `universal` 查询。支持 Android ABI 别名。 |
| `package_type` | 可选安装格式。默认 Android `apk`、Windows `exe`、macOS `dmg`、iOS `app_store`；可显式请求 `msix`、`pkg` 或 `ipa` 等该平台支持的格式。 |
| `current_version` | 可选 SemVer；当前版本不低于候选版本时返回 `data: null`。 |
| `channel` | 可选，默认 `stable`。 |
| `android_api` | Android 可选；若发布包要求更高 API，未上报或过低时不会返回该包。 |
| `os_version` | 可选 SemVer，用于 `min_os_version` 兼容过滤。未提供时，只返回未设置 `min_os_version` 的 artifact。 |

推荐客户端按以下方式构造目标参数：

| 客户端目标 | 查询参数 |
|---|---|
| Android 32 位 ARM | `platform=android&arch=armeabi-v7a&package_type=apk`，服务端归一化为 `armv7`。 |
| Android 64 位 ARM | `platform=android&arch=arm64-v8a&package_type=apk`，服务端归一化为 `arm64`。 |
| Windows x64 | `platform=windows&arch=x86_64&package_type=exe`，也可显式请求 `msix`。 |
| macOS Apple Silicon | `platform=macos&arch=arm64&package_type=dmg`，也可显式请求 `pkg`。 |
| macOS Intel | `platform=macos&arch=x86_64&package_type=dmg`。 |
| iOS App Store | `platform=ios&package_type=app_store`；省略架构时按 `universal` 查询。 |

Android 不允许省略 `arch`，也不会在 `armv7` 与 `arm64` 之间回退。非 Android 省略 `arch` 并不表示“自动识别 CPU”，而是只查询显式发布的 `universal` artifact；若只发布了 `x86_64` 或 `arm64` 包，客户端必须上报对应架构。

成功响应的 `artifact.download_url` 是有效期 15 分钟的预签名 GET URL。包含预签名 URL 的响应使用 `Cache-Control: private, max-age=60`，不得进入共享缓存。响应带 `ETag`，客户端可发送 `If-None-Match` 取得 `304 Not Modified`；ETag 包含平台、架构、安装格式、频道、Android API、`os_version` 和当前版本等选择条件，并在签名 URL 的有效期窗口内轮换，避免旧 URL 过期后客户端一直收到 304。

无匹配平台、架构或安装格式的已发布 artifact 时返回 `404` 和 `暂无匹配的平台、架构或安装格式`。目标组合存在，但 `min_android_api` 或 `min_os_version` 不兼容时返回 `404` 和 `暂无兼容当前系统版本的安装包`。这两种情况都不能解释为“当前已是最新版本”；只有找到兼容 artifact 且 `current_version` 不低于候选版本时才返回 `200` 与 `data: null`。公共查询按 IP 限制为每分钟 30 次。

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "has_update": true,
    "release": {
      "version": "1.2.0",
      "channel": "stable",
      "changelog": "修复音频连接问题",
      "force_update": false,
      "min_supported_version": "1.0.0"
    },
    "artifact": {
      "platform": "android",
      "arch": "arm64",
      "android_abi": "arm64-v8a",
      "package_type": "apk",
      "file_name": "draarl-1.2.0-arm64-v8a.apk",
      "file_size": 52428800,
      "sha256": "<64-char-hex>",
      "download_url": "https://…",
      "url_expires_at": "2026-07-29T12:00:00Z"
    }
  }
}
```

当 `current_version` 不低于选中的兼容版本时，接口不会生成下载链接，返回：

```json
{
  "code": 200,
  "message": "当前已是最新版本",
  "data": null
}
```

参数非法返回 `400`；不存在目标平台、架构或安装格式返回 `404` 和 `暂无匹配的平台、架构或安装格式`；目标存在但 `android_api` 或 `os_version` 不兼容时返回 `404` 和 `暂无兼容当前系统版本的安装包`。存储未启用或临时无法生成签名下载地址时返回 `503`，客户端不应把这些响应当作“当前已是最新版本”。

客户端下载完成后必须先验证 `sha256`，再交给平台安装器处理。`force_update` 与 `min_supported_version` 的具体强制交互由客户端决定。
