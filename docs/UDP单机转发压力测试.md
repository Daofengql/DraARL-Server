# UDP 单机转发压力测试

本文记录 DraARL 单机 UDP fan-out 的优化前基线，以及 2026-07-20 全平台通用优化后的 Windows 本机和 Linux 4C8G Hyper-V 完整部署结果。测试用于定位代码瓶颈和辅助容量决策，不是生产 SLA；真实网卡、FRP、IPv6 和长时间稳态仍需在目标环境复测。

## 结论

- 优化前的稳定平台约为 5 万 pps；优化后在相同 Windows 回环环境达到 200,678 pps、零丢包，稳定吞吐至少提高 4 倍。
- Ubuntu 22.04 的 4 vCPU/8 GiB VM 内同时运行 MySQL、Redis、DraARL 和纯 Go 压测端，9000 台、20ms 连续 30 秒达到 449,950 pps、1,475.84 Mbps 应用层流量、零丢包，平均延迟 9.45ms。
- Linux 9000 台、19ms 时首次淘汰 1 个完整 fan-out 帧（0.1898%）；15ms 时实际转发 573,236 pps、丢 4.50%，10ms 时维持约 554,338 pps、丢 38.4%。同机完整部署的保守零丢包上限是至少 45 万 pps，过载吞吐平台约 50 至 57 万 pps。
- Linux 20000 个真实 UDP socket、120ms 时达到 167,992 pps、零丢包；这是纯 Go bench 当前允许的最大设备档，不是服务端设备容量上限。
- 9000 个接收端、45ms 间隔时达到 200,678 pps、658.22 Mbps DraARLv1 应用层流量，平均延迟 13.5ms。
- 9000 个接收端、40ms 间隔时实际转发 220,476 pps，丢弃 2.0%，平均延迟升至 86.6ms，已经进入过载区。
- 15000 个在线设备、120ms 间隔时达到 125,992 pps、零丢包；18000 台在建立连接时由 Windows 压测进程先耗尽 socket/buffer 资源，未测到服务端上限。
- 5 个独立群组、每组 1000 台设备、5 个设备同时发送 Type 5 普通语音时为 41,625 pps、零丢包，并实际生成和清理 5 份录音。
- 1/2/4/8 writer 在 5000 台、120ms 下均零丢包，但平均延迟依次为 35.9/17.7/10.6/8.2ms，因此当前 Windows 配置选择 8 writer。
- Linux 4 vCPU 上的 1/2/4/8 writer 平均延迟依次为 11.08/5.39/5.18/5.74ms，因此 Linux 测试选择 4 writer；writer 数应按 CPU 和平台实测选择。
- Linux 45 万 pps 的稳定档已超过常见公网出口和 1GbE 可承载范围；当前不再计划 `sendmmsg/recvmmsg/SO_REUSEPORT` 等 Linux 专属发送优化。
- 对当前业余无线电使用规模，单机容量已不是近期实现集群的充分理由。异地接入、高可用和超大路由域拆分仍是集群的独立价值。

## 优化内容

本轮不是简单增加 goroutine，而是调整整个热路径：

1. fan-out 从每目标一个 job 改为每完整帧一个 job，接收者快照使用 `netip.AddrPort` 并预分片。
2. 每个 writer 使用独立的 Go `poll.FD` 和写锁；Windows 使用链式 socket 复制建立全部 8 个 writer，同时保持服务器监听源端口。
3. 同一目标固定落到同一 writer，保持帧顺序；队列过载时淘汰最旧完整帧，不随机截断接收者。
4. 入站改为单 reader 直接移交缓冲，并按 username+SSID 分片，避免同设备换源端口后乱序。
5. 路由快速解码不再为语音物化 password/callsign 等无用字符串；转发前仍清空 password 字段。
6. receiver snapshot 从每帧地址处理改为成员变化失效、30 秒兜底，并在构建时完成去重和 writer 分片。
7. UDP 到 WebSocket 广播只复制一份只读 payload，多个连接共享引用；慢连接队列满时只计数。
8. 删除设备运行时缓存的 10000 条硬上限，并批量加载 owner 信息。

## 当前瓶颈

### 逐目标系统调用已不是当前业务瓶颈

标准后端仍对每个目标执行一次 `WriteToUDPAddrPort`，理论上可用 Linux `sendmmsg` 继续减少系统调用。但当前 30 秒零丢包基线已经达到 449,950 pps、1,475.84 Mbps 应用层流量，先于程序触顶的会是常见公网出口、1GbE 物理链路和实际终端规模。继续增加 Linux 专属后端的复杂度没有现实收益，因此本轮明确停止在跨平台 standard 后端；只有未来出现超过当前边界的真实业务负载时才重新立项。

### 实时帧服务时间

Windows 在约 20 万 pps 时队列延迟仍健康，约 22 万 pps 开始完整淘汰帧；Linux 4C8G 同机布局在 45 万 pps 连续 30 秒仍健康，47.4 万 pps 偶发淘汰一帧，50 万 pps 以上排队延迟明显增长。增大队列只会把丢包转换成陈旧语音，因此保留当前 120ms 帧龄和完整帧淘汰策略作为容量保护，不再通过扩大队列追求压测数字。

### Windows 回环与压测器

服务端和负载进程共享同一台主机及 Windows 网络栈。18k socket 失败、40ms 档的 4 核服务端 CPU 和约 4 核负载端 CPU 都说明测试结果包含回环交换及接收器成本。需要两机真实网卡测试才能区分应用、内核、NIC 和接收端上限。

### Linux 同机资源竞争

Linux 过载档里 DraARL 约占 1.85 核，压测端约占 1.45 核，此外还有回环内核路径和同机依赖。吞吐平台出现时并非 DraARL 单进程已经用满 4 核，而是完整 VM 接近联合资源边界。两机测试可能提高服务端结果，也可能先撞到 NIC 线速；在此之前不能把约 57 万 pps 当成生产发送能力。

### 尚未覆盖

- 两机真实网卡及 1/2.5/10GbE 线速
- IPv6、FRP/PROXY 聚合流、NAT
- 大量慢 WebSocket 客户端
- 持续切组、禁收、上下线等成员 churn
- 30 分钟与 24 小时 soak、CPU/mutex/block profile

## 容量建议

在这台 Windows 主机上，100,000 pps、12000 台设备、120ms 是已经实测的零丢包档，并为 200,000 pps 的本机拐点保留约 50% 余量。它可以作为开发环境的保守参考，不应直接换算成互联网生产承诺。

在 Linux 4C8G VM 的完整同机布局中，20,000 台/120ms 和 449,950 pps/20ms 已分别通过零丢包测试。若只按当前回环结果为应用留约三分之一余量，可用 300,000 pps 作为后续真实网络容量验证的起点；这仍不是生产 SLA，也不是继续优化发送器的目标。

真实部署还要受网卡线速影响。410 字节应用报文之外仍有 UDP/IP、链路层和帧间隙开销；Linux 的 30ms 档已是 985.86 Mbps 应用层流量，25ms 以上结果只有回环或超过 1GbE 的链路才可能承载。生产容量应在目标 Linux 服务器和真实网卡上重复测试后确定。

对当前面向业余无线电的规模，建议先保持单机架构。只有业务出现异地接入、高可用要求，或单个路由域在真实网络上确实超过单机余量时，再实现一主多从 UDP 子节点；中心节点应只向每个目标子节点发送一份帧，由子节点完成本地 fan-out。

## 复现

当前 bench 固定使用 Type 5，以下命令用于复测当前正式语音路径。

单组 120ms 分档：

```bash
go run ./test/bench/udp_fanout -confirm-test-data -server-pid <PID> -levels 3000,5000,6000,8000,9000 -duration 10s -interval 120ms
```

单组高包速：

```bash
go run ./test/bench/udp_fanout -confirm-test-data -server-pid <PID> -levels 9000 -duration 10s -interval 45ms
```

Linux 4C8G 的 30 秒零丢包边界复测：

```bash
ulimit -n 200000
./udp_fanout -confirm-test-data -server-pid <PID> -levels 9000 -duration 30s -interval 20ms
```

5 个群组、每组 1000 台、Type 5 和录音：

```bash
go run ./test/bench/udp_fanout -confirm-test-data -server-pid <PID> -groups 5 -levels 5000 -duration 15s -interval 120ms
```

Type 5 只有在站点通信录制设置 `comm.enabled=true` 时才会实际落盘；关闭时仍可测完整普通语音转发，但录音数应为 0。具体参数、安全说明和异常中断后的清理方式见 `test/bench/udp_fanout/README.md`。
