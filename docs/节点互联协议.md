# Type 0 节点互联协议

本文描述 DraARL 中心与边缘节点之间的内部协议。普通设备和第三方客户端只应使用公开的 DraARLv1 Type 1-5；Type 0 只能由通过 TLS 鉴权的节点会话使用。

## 1. 拓扑与端口

- 同一个 `draarl` 二进制默认运行中心模式，使用 `--edge` 进入无数据库边缘模式。
- 中心负责 HTTP、MySQL、Redis、完整路由和权限；边缘只负责普通设备接入、本地转发和节点互联。
- TLS 控制面使用 `Interconnect.ControlListen`，默认 `60100/tcp`。
- Type 0 UDP 数据面复用中心 `System.Port` 和边缘 `Edge.Listen`，默认 `60050/udp`，不另开数据端口。
- 边缘的设备包和 Type 0 包由同一个双向 UDP socket 收发并按已认证节点会话分流。

当中心位于另一台主机时，`Edge.Listen` 必须使用 `:60050`、`0.0.0.0:60050` 或可到达的网卡地址。绑定 `127.0.0.1` 会同时固定出站 Type 0 的源地址，只适用于中心与边缘位于同一主机的测试。

## 2. 数据路径

```text
设备 -> 来源边缘 -> 本地 fan-out
                  -> 一份 RelayUpstream -> 中心
                                          -> 中心本地 fan-out
                                          -> 每个目标边缘一份 RelayDownstream
                                                                -> 本地 fan-out
```

中心按 `SessionID + SessionEpoch` 校验来源所有权，并从权威路由重新确定通信域和收发权限。中心不会把 Downstream 发回来源边缘；目标边缘也不会再次上传 Downstream。

Type 4 文本直接转发。Type 5 语音必须先通过 TLS 控制面的 `SpeakerLease` 取得中心话权，同一通信域同时只允许一个有效说话人。

## 3. Type 0 UDP 信封

UDP 信封最大 1400 字节。整数均使用网络字节序。

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 4 | `DraA` |
| 4 | 2 | 完整包长 |
| 6 | 32 | `SourceNodeID`，零填充 |
| 48 | 1 | Type，固定为 `0` |
| 86 | 4 | `NOD0` |
| 90 | 1 | 节点协议版本 |
| 91 | 1 | 子类型 |
| 92 | 2 | Flags |
| 94 | 8 | `ClusterEpoch` |
| 102 | 8 | `ProjectionVersion` |
| 110 | 8 | `NodeSessionID` |
| 118 | 8 | `MessageID` |
| 126 | 8 | `SentAtMillis` |
| 134 | 1 | `HopCount` |
| 135 | 4 | `KeyEpoch` |
| 139 | 4 | Payload 长度 |
| 143 | 可变 | Payload |
| 末尾 | 32 | HMAC-SHA256 |

HMAC 覆盖信封头和 Payload。会话密钥、NodeSessionID 和 KeyEpoch 由已认证 TLS 控制连接建立；普通设备字段不参与节点身份判断。

节点在 TLS 握手中同时提交支持的最小/最大协议版本、功能位和必需功能位。中心
选择双方共同支持的最高版本，并只启用功能位交集；版本区间不相交，或任一方的
必需功能不在交集中时，凭据校验前即拒绝连接。当前协议范围为 `1..1`，功能位为：

| 位 | 能力 |
|---:|---|
| `0` | 路由快照、增量与 ACK |
| `1` | Type 0 UDP Relay |
| `2` | 边缘设备短期会话 |
| `3` | Type 3 配置上下发 |
| `4` | 跨节点 Speaker Lease |
| `5` | 节点运行指标 |
| `6` | 在线节点凭据轮换与持久化确认 |

前 3 位是当前运行所必需的能力。功能协商结果绑定到本次随机
`NodeSessionID`，断线重连后必须重新协商。

## 4. 子类型

| 值 | 名称 | 通道 | 方向 |
|---:|---|---|---|
| `0x01` | NodeEnroll | TLS | 边缘与中心 |
| `0x03` | NodeAuth | TLS | 边缘与中心 |
| `0x05` | NodeHeartbeat | TLS | 双向状态与指标 |
| `0x06` | NodeDataBind | TLS 挑战、UDP 证明 | 双向 |
| `0x07` | NodeCredential | TLS | 中心下发轮换凭据、边缘持久化后确认 |
| `0x10` | RouteSnapshotBegin | TLS | 中心到边缘 |
| `0x11` | RouteSnapshotChunk | TLS | 中心到边缘 |
| `0x12` | RouteSnapshotCommit | TLS | 中心到边缘 |
| `0x13` | RouteDelta | TLS | 中心到边缘 |
| `0x14` | RouteAck | TLS | 边缘到中心 |
| `0x15` | RouteResyncRequest | TLS | 边缘到中心 |
| `0x20` | DeviceAuth | TLS | 双向 |
| `0x21` | DeviceSessionRenew | TLS | 双向 |
| `0x22` | DeviceSessionReport | TLS | 边缘到中心 |
| `0x23` | DeviceSessionRevoke | TLS | 中心到边缘 |
| `0x24` | DeviceConfig | TLS | 双向 Type 3 配置 |
| `0x28` | SpeakerLease | TLS | 双向 Type 5 话权 |
| `0x30` | RelayUpstream | UDP | 边缘到中心 |
| `0x31` | RelayDownstream | UDP | 中心到边缘 |

控制面使用 4 字节长度前缀的 JSON 帧承载握手消息和经过 HMAC 的 Type 0 控制信封，最大帧 65535 字节。路由快照按 32 KiB 原始块分片、校验后原子提交。

Flags 的 `0x0010` 位表示关键扩展。接收方遇到未知的非关键子类型时只丢弃该帧；
遇到未知关键子类型时必须返回通用协议错误并关闭节点会话。错误响应不回显原始
Payload、凭据或密钥。

## 5. 路由版本与帧龄

- `ClusterEpoch` 在中心世代变化后失效旧状态。
- 每个边缘拥有独立、连续的 `ProjectionVersion`，无关节点变化不会制造版本空洞。
- Downstream 携带目标边缘所需版本；边缘落后时最多等待 1024 帧和 200 ms，追上版本后释放，否则丢弃。
- `MessageID` 在节点会话内经过固定 4096 位重放窗口检查。

时间限制分为两层：

1. UDP 入口使用 `SentAtMillis` 做 `±2 s` 的粗粒度会话新鲜度检查，用于拒绝明显陈旧或未来的包。节点应启用系统时间同步，但不要求服务器时钟精确到实时帧队列的毫秒级。
2. 包到达边缘后记录本机单调时间。200 ms 只限制本地投影等待和队列积压，不把国内外公网 RTT 或两台服务器的墙上时钟偏差算作本地排队。

因此 150 ms 等正常跨地域网络延迟不会被 200 ms 本地队列时限直接拒绝。若需要观测跨地域延迟，应在 TLS 控制面增加 RTT/时钟偏差指标，而不是把跨主机墙上时钟作为实时转发的硬条件。

## 6. 安全与资源隔离

- 首次注册 token 只用于换取长期节点身份；identity 文件不得写入日志或公开接口。
- 管理员轮换凭据时，中心先原子安装新凭据并在有限宽限期内保留旧凭据哈希。在线边缘通过 TLS 收到新凭据，必须先原子写入 identity 文件再确认；中心只有收到确认才报告在线下发成功。离线节点需使用仅显示一次的响应手工更新 identity。
- 吊销操作同时清除注册、当前和宽限期凭据并递增凭据世代，随后断开当前会话；单独的强制下线只重置连接，不吊销仍有效的凭据。
- 数据地址只能通过 TLS 下发的随机挑战和 UDP HMAC 证明绑定或重绑，普通中继包不能改变地址。
- 有效 Type 0 绕过普通设备 IP 限速，但仍受独立的每节点 PPS、带宽、队列、会话数和全局节点数上限约束。
- HMAC 失败、身份不符、过期、重放、未绑定地址、绑定拒绝、队列满和硬限额分别计数。
- inner packet 只允许规范化后的 Type 4/5，设备密码和 JWT 不进入 UDP 中继载荷；Type 3 只走 TLS 控制面。
