# 11. v1.1.5-alpha1 升级说明

`v1.1.5-alpha1` 增加可选的 Type 0 中心/边缘互联、并行 UDP fan-out、边缘节点
管理和设备入口发现。普通设备协议仍使用原编号的 Type 1-5；未启用
`Interconnect` 时，中心继续按单机方式接入和转发。

## 1. 升级前检查

- 备份 MySQL、对象存储、当前二进制和 `config.yaml`。
- 若已经运行边缘，同时备份每台边缘的 `edge-identity.json`；该文件等同长期凭据。
- 记录当前中心 UDP/HTTP 端口、反向代理和防火墙规则。
- 校验发布包 SHA-256，并执行 `./draarl -v` 确认版本为 `v1.1.5-alpha1`。
- 保持中心和边缘系统时间同步。Type 0 允许 `±2s` 的粗粒度时钟误差。

## 2. 数据库迁移

已有数据库必须在备份后显式执行一次：

```bash
./draarl -c config.yaml -auto-migrate
```

迁移会增加边缘节点、入口归属、节点指标和凭据生命周期所需字段。新增字段对未启用
互联的单机部署没有行为影响。

迁移还会处理已停用的群组呼号和设备准入白名单列。若历史
`allow_callsign_ssid` 中仍有非空值，迁移会中止，不会静默删除；确认并清理历史值后
再重试。列一旦删除，只有升级前数据库备份可以恢复其历史内容。

## 3. 推荐上线顺序

1. 保持 `Interconnect.Enabled: false`，先升级中心并验证普通 Type 1-5、HTTP、
   WebSocket、录音和设备管理。
2. 配置中心 TLS 证书和 `Interconnect.ControlListen`，再启用互联。UDP 数据面仍
   复用 `System.Port`，不开放第二个 Type 0 UDP 端口。
3. 在后台逐个创建边缘节点，保存仅显示一次的注册凭据。
4. 在边缘使用 `./draarl --edge -c config.yaml` 启动，确认 identity 文件已按
   `0600` 权限持久化、节点在线、投影 ACK 追平且 drop/error 为 0。
5. 先让少量测试设备通过边缘接入，验证 Type 3 配置、Type 4 文本、Type 5 语音、
   切组和收发控制，再逐步迁移设备。
6. 最后启用公开入口；客户端从入口列表自行 ICMP 测速选择，不由平台代测。

中心必须先升级。旧版本不理解 Type 0，不能作为新边缘的中心；边缘停止不会影响
中心继续接受普通设备直连。

## 4. 上线验证

- `GET /api/edge-nodes`：节点在线、连接数正确、投影版本与 ACK 一致、同步错误为空。
- `GET /api/udp/metrics`：队列没有持续堆积，`frames_dropped`、`frames_stale`、
  `write_errors` 符合预期。
- 设备列表：当前或最近入口显示管理员设置的节点昵称，不向普通用户显示内部 NodeID。
- 入口发现：只返回启用且健康的节点，不返回控制地址、远端地址、凭据和内部指标。
- 凭据轮换：在线边缘先持久化新 identity 后确认；离线轮换的新凭据只显示一次。

## 5. 快速回滚

1. 停止发布边缘入口，并让客户端恢复中心 UDP 地址。
2. 停止全部边缘进程；中心不会再向离线边缘调度数据。
3. 将 `Interconnect.Enabled` 设为 `false`，重启当前中心，确认普通设备已直接接入。
4. 若必须回退旧二进制，继续使用升级前的 `config.yaml` 和二进制。新增数据库列可
   暂时保留，旧程序不会使用；不要为了回滚临时手工删列。
5. 只有需要恢复已删除的历史群组字段时，才从升级前 MySQL 备份恢复到独立数据库，
   核对后再决定是否整库回退。

边缘 identity、注册凭据和长期凭据不得写入仓库、工单或普通日志。回滚结束后若不再
使用某个边缘，应在后台吊销其凭据，而不只是停止进程。

## 6. Alpha 阶段限制

本地 Linux/Windows 回归、竞态测试和 Ubuntu 多边缘回环压力已覆盖。公网 TLS/UDP、
FRP PROXY Protocol v2、IPv6、跨地域高延迟和真实网卡线速仍应在目标部署环境复测；
这些结果不构成生产 SLA。
