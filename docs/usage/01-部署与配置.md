# 01. 部署与配置

## 1. 环境要求

| 依赖 | 建议版本 | 必需性 | 说明 |
|---|---:|---|---|
| Go | 1.25+ | 必需 | 后端构建和运行。 |
| Node.js | 20+ | 前端构建必需 | `www` 使用 Vite 7 和 React 19。 |
| MySQL/MariaDB | MySQL 5.7+ / MariaDB 10.3+ | 必需 | 主业务数据库。 |
| Redis | 6.0+ | 推荐 | refresh token 存储，不可用时降级到内存。 |
| MinIO | 兼容 minio-go/v7 | 可选 | 对象存储；也可改用本地磁盘（`Storage.Driver=local`）。 |
| Keycloak | 可选 | 可选 | SSO 登录。 |

## Docker Compose 快速部署（Linux）

仓库根目录的 `compose.yaml` 提供 DraARL、MySQL、Redis 和 MinIO 的完整
单机部署。DraARL 镜像使用多阶段构建，最终镜像只包含静态 Go 二进制、证书、
时区数据和配置生成工具，并以非 root 用户运行。

```bash
cp .env.example .env
```

部署前必须修改 `.env` 中的 MySQL、Redis、MinIO 密码，并核对：

- `DRAARL_PUBLIC_URL`：浏览器访问 DraARL 的 Origin，例如
  `https://radio.example.com`。
- `DRAARL_MINIO_ENDPOINT`：DraARL 容器和浏览器都可以直接访问的 MinIO 已发布地址
  `host:port` 或反代域名；不要填写 Compose 内部服务名 `minio:9000`。
- `DRAARL_MINIO_USE_SSL`：上述已发布地址是否使用 HTTPS。
- `DRAARL_HTTP_PORT`、`DRAARL_UDP_PORT`：宿主机发布端口。

启动并检查健康状态：

```bash
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:${DRAARL_HTTP_PORT:-9000}/healthz
docker compose logs draarl
```

首次启动过程如下：

1. MySQL、Redis、MinIO 分别通过健康检查。
2. DraARL 入口脚本在 `draarl-config` 命名卷中生成一次
   `/var/lib/draarl/config.yaml`；未显式提供的 JWT/AES 密钥使用系统随机源生成。
3. 默认携带 `-auto-migrate` 初始化或升级结构；旧版 `minio` 驱动会在桶不存在时
   创建 MinIO bucket，并输出首次管理员凭据。
4. 后续重启复用同一配置和全部数据卷，不会重新生成密钥。

Compose 默认将 MinIO 设为 `MINIO_BROWSER=off`，只发布 9000 S3 API 端口，
不启动或发布 9001 Web Console。DraARL 不会修改 bucket policy；安装包、固件和
其他对象都通过短期预签名 URL 访问，桶应始终保持私有。前端静态资源由 DraARL
主程序直接提供，不写入对象存储。

`DRAARL_AUTO_MIGRATE=false` 可关闭后续容器启动时的显式迁移；完全空库仍会按
DraARL 的空库规则自动初始化。Compose 环境变量只负责首次生成配置，已有配置
不会被重写。需要修改完整配置时可导出、编辑并放回命名卷：

```bash
docker compose cp draarl:/var/lib/draarl/config.yaml ./config.yaml
# 编辑 config.yaml
docker compose cp ./config.yaml draarl:/var/lib/draarl/config.yaml
docker compose restart draarl
```

`docker compose down` 保留数据；`docker compose down -v` 会删除数据库、Redis、
MinIO 和 DraARL 配置卷，仅限明确需要清空部署时使用。生产升级前应备份命名卷，
并在宿主机按需要提高 UDP `rmem_max`/`wmem_max`，容器不能突破宿主机内核上限。

## 4. 核心配置说明

### 4.1 System

| 字段 | 说明 |
|---|---|
| `Host` | UDP 监听地址，空字符串表示所有网卡。 |
| `Port` | UDP 服务端口，示例为 `60050`。 |
| `LogPath` | 日志文件路径，空字符串表示不输出到文件。 |
| `IPfile` | IP 地址库路径，默认 `./ipinfo.ipdb`。 |
| `ProxyProtocol` | 可配置 `v2`，用于从 frp 等代理获取真实客户端 IP。 |

### 4.2 Database

| 字段 | 说明 |
|---|---|
| `Host` / `Port` | MySQL 地址。 |
| `User` / `Password` | 数据库账号。 |
| `DBName` | 数据库名。 |
| `Charset` / `Collate` | 默认 `utf8mb4` / `utf8mb4_unicode_ci`。 |
| `MaxOpenConns` | 最大打开连接数，默认 25。 |
| `MaxIdleConns` | 最大空闲连接数，默认 5。 |
| `MaxLifetime` | 连接最大存活时间，单位秒，默认 300。 |

### 4.3 Redis

Redis 用于 refresh token 存储。程序启动时优先连接 Redis；如果连接失败，会降级到内存存储。内存模式可以运行，但服务重启后 refresh token 状态会丢失，生产环境建议配置 Redis。

| 字段 | 说明 |
|---|---|
| `Host` / `Port` | Redis 地址。 |
| `Password` | Redis 密码。 |
| `DB` | Redis 数据库编号。 |
| `Prefix` | Key 前缀，默认 `draarl`。 |
| `DialTimeoutSec` / `ReadTimeoutSec` / `WriteTimeoutSec` | 连接和读写超时。 |
| `PoolSize` | 连接池大小。 |

### 4.4 Web

| 字段 | 说明 |
|---|---|
| `Host` | HTTP 监听地址，空字符串表示所有网卡。 |
| `Port` | HTTP/API/WebSocket 服务端口。 |
| `FrontendURL` | 前端对外地址，用于 SSO 回调重定向，也会加入 Origin 白名单。 |
| `AllowedOrigins` | 允许访问 API 和 WebSocket 的页面来源。生产环境必须正确配置。 |

生产环境注意：

- 后端会校验 `Origin`/`Referer`。
- release 构建下如果没有可解析的 `FrontendURL` 或 `AllowedOrigins`，程序会启动失败。
- API 网关会拒绝 URL query 中出现 token 类参数，例如 `token`、`access_token`、`refresh_token`、`jwt`。

### 4.5 Keycloak

| 字段 | 说明 |
|---|---|
| `Enabled` | 是否启用 SSO。 |
| `Name` | 前端显示名称。 |
| `BaseURL` | Keycloak 服务器地址。 |
| `Realm` | Realm 名称。 |
| `ClientID` / `ClientSecret` | 客户端配置。 |
| `RedirectURI` | 后端 `/api/sso/callback` 回调地址。 |

### 4.6 存储（Storage / S3 兼容对象存储）

系统通过统一存储抽象支持 `local`、MinIO、Cloudflare R2、腾讯云 COS 和阿里云 OSS。除 local 外，所有实现都通过同一个 S3 V4 驱动工作，不会为每个厂商复制上传、校验或发布流程：

| `Storage.Driver` | 说明 |
|---|---|
| `minio` | 使用 `Storage.MinIO` 连接对象存储；支持 S3 预签名直传。 |
| `s3` / `r2` / `cos` / `oss` | 使用 `Storage.S3`；`r2`、`cos`、`oss` 是 S3 兼容别名。 |
| `local` | 文件写入 `Storage.Local.RootPath`；明确允许公开的站点图片可走 `/files/*`，其他对象使用签名 GET。 |
| 空 | 若 `Storage.MinIO.Endpoint` 非空则选 minio，否则 local。 |

| 字段 | 说明 |
|---|---|
| `Storage.Local.RootPath` | 本地存储根目录，默认 `./data/storage`。 |
| `Storage.Local.BaseURL` | 公开 URL 前缀，空则使用 `/files`。 |
| `Storage.UploadLimits.ClientResourceBytes` | 通用客户端资源直传上限，默认 536870912（512 MiB）。固件继续使用独立的 16 MiB 限制。 |
| `Storage.MinIO.Endpoint` | 后端连接 MinIO 的地址，可以使用容器网络或内网地址。 |
| `Storage.MinIO.PublicEndpoint` | 可选的对外 `host:port`；预签名 URL 使用此地址，留空回退到 `Endpoint`。 |
| `Storage.MinIO.AccessKey` / `SecretKey` | 凭据。 |
| `Storage.MinIO.UseSSL` | 是否使用 HTTPS。 |
| `Storage.MinIO.PublicUseSSL` | `PublicEndpoint` 是否使用 HTTPS。 |
| `Storage.MinIO.Bucket` | 默认桶名。 |
| `Storage.MinIO.DownloadURLPrefix` | 可选，仅替换预签名 GET 的访问前缀；预签名 PUT 不使用它。 |
| `Storage.ActiveProfile` | 当前运行的命名 profile。设置后优先于旧的 `Driver`/`MinIO` 配置。 |
| `Storage.Profiles.<name>.Driver` | `local`、`s3`、`minio`、`r2`、`cos` 或 `oss`。 |
| `Storage.Profiles.<name>.S3.Endpoint` | 后端连接的 S3 API 地址，可写 `host:port` 或完整 `http(s)://` URL；显式 scheme 优先于 `UseSSL`。 |
| `Storage.Profiles.<name>.S3.PresignEndpoint` | 浏览器实际访问的 S3 API 地址，只用于生成 PUT/GET 签名；显式 scheme 优先于 `PresignUseSSL`。 |
| `Storage.Profiles.<name>.S3.DownloadURLPrefix` | 高级选项：替换预签名 GET 的 URL 前缀，供用户自行配置的反向代理使用；不代表对象公开。 |
| `Storage.Profiles.<name>.S3.Region` / `BucketLookup` | region 和桶寻址方式（`auto`、`path`、`dns`）。 |
| `Storage.Profiles.<name>.S3.SessionToken` | 可选 STS 会话令牌。 |
| `Storage.Profiles.<name>.S3.AutoCreateBucket` | 仅开发 MinIO 建议设为 `true`；公有云保持 `false`，由部署侧预创建 bucket。 |

未显式填写 `BucketLookup` 时，`r2` 和 `minio` 默认使用 `path`，`cos` 和 `oss` 默认使用 `dns`，通用 `s3` 使用 `auto`；其他值会在启动时直接报错，不会静默回退。推荐端点格式：R2 使用 `<account-id>.r2.cloudflarestorage.com`，Region 留空时自动设为 `auto`；COS 使用 `cos.<region>.myqcloud.com`、真实 Region 及包含 AppID 的 bucket 名；OSS 使用 `oss-<region>.aliyuncs.com` 和真实 Region。COS、OSS 缺少 Region 时会拒绝启动。完整 profile 示例见 `config.yaml.example`。

运行凭据至少需要检查 bucket、列举指定前缀、读取对象、写入对象和删除对象的权限；`Promote` 还需要读取 staging 源对象并在 final key 执行服务端复制。建议把权限限制到业务 bucket，并尽可能限制到 `staging/`、`client-resources/`、`firmware/`、`assets/` 等应用前缀。应用不会修改 bucket policy；若启用存储迁移，还需覆盖迁移源和目标所需权限。

`AccessKey`、`SecretKey` 和 `SessionToken` 支持精确的 `${ENV_NAME}` 引用。变量在创建存储客户端时解析，解析值不会回写配置文件；变量缺失或为空会使存储初始化失败并明确指出字段。也可以通过容器 Secret 生成未跟踪的生产配置。

旧版本顶层 `MinIO:` 配置会在启动时自动迁移到 `Storage.MinIO`；显式设置 `Storage.Driver: local` 时不会迁移旧 MinIO 配置。旧 `BasePath` 和 `PublicBaseURL` 会打印弃用提示并迁移为 `DownloadURLPrefix`，不再产生匿名、无签名 URL。

上传策略固定为：

- **代理上传**（需服务端图像处理）：头像、Logo、Favicon
- **浏览器直传**（presign → PUT → complete）：资源中心、固件、操作证、通用客户端资源（含安装包、模型和字库）

直传对象先写入按用户隔离的 staging 路径，complete 校验签名授权和实际大小后才提升为不可变对象。超过 24 小时未完成的 staging 对象会自动清理；管理员可在资源页重新识别自己的已完成 staging 上传并重签 complete 凭证。客户端资源和固件通过短时下载 URL 返回；local 驱动也使用 `/api/storage/get` 的短时签名 URL，`client-resources/`、`firmware/` 和 `staging/` 不能由 `/files/*` 永久访问。

资源中心、头像、站点图片、操作证和通联录音的历史响应字段也通过统一读取 URL 策略生成：local 仅对明确允许的头像、Logo 和 Favicon 返回稳定 `/files/*` 地址，其他对象使用签名 GET；S3 兼容存储始终返回预签名 GET URL，不要求也不应把 bucket 改为公共读取。前端不应持久化签名 URL，页面长时间打开后应重新请求相应业务接口。

**S3 兼容直传 CORS 要求**：

- 允许前端 Origin 的 `PUT`、`GET`、`HEAD`（以及预检 `OPTIONS`）
- 允许请求头 `Content-Type` 以及供应商签名流程需要的 `x-amz-*` 请求头
- 暴露响应头 `ETag`
- 生产建议 HTTPS 反代 MinIO，并保证签名 URL 中的 host 浏览器可达
- 预签名依赖服务端与对象存储时间一致；生产环境应启用 NTP 时间同步
- 应通过 Secret、环境变量或未跟踪配置提供 AccessKey/SecretKey，示例文件不得填写生产密钥

`DownloadURLPrefix` 不是 CDN 功能。程序先针对 `PresignEndpoint` 生成完整 S3 V4
预签名 GET，再把浏览器访问前缀替换为该值，并保留对象路径和全部 `X-Amz-*`
查询参数。代理必须在回源时恢复签名使用的 Host 和原始 S3 路径，否则会返回
`SignatureDoesNotMatch`。DraARL 不配置或检测 CDN 缓存键、回源 Header、方法限制
和边缘鉴权；未充分理解 S3 V4 canonical request 时应保持该字段为空。

对私有对象使用缓存时，不要简单从缓存键中忽略全部签名参数。否则合法请求预热后，
伪造、缺失或过期签名也可能直接命中缓存并绕过源站鉴权。缓存 TTL 也不应超过预签名
URL 有效期。此类高级代理配置由部署方自行验证，项目只保证未配置前缀时的标准 S3
预签名行为。

可使用同一套可选契约测试验证 MinIO、R2、COS 或 OSS；当前 MinIO 已通过含 CORS 的契约，R2、COS 和 OSS 已通过除部署 Origin CORS 外的存储契约和完整客户端资源 HTTP 生命周期。测试会在指定桶的
`contract-tests/` 和 `staging/contract-tests/` 前缀创建并清理临时对象，覆盖 Put、Stat、Open、Walk、Delete、预签名 PUT/GET、服务端复制、不可覆盖 final key 和 CORS：

```bash
DRAARL_S3_TEST_PROVIDER=minio \
DRAARL_S3_TEST_ENDPOINT=127.0.0.1:9000 \
DRAARL_S3_TEST_PRESIGN_ENDPOINT=127.0.0.1:9000 \
DRAARL_S3_TEST_ACCESS_KEY=test-access-key \
DRAARL_S3_TEST_SECRET_KEY=test-secret-key \
DRAARL_S3_TEST_BUCKET=draarl-contract \
DRAARL_S3_TEST_BUCKET_LOOKUP=path \
DRAARL_S3_TEST_CORS_ORIGIN=https://admin.example.com \
go test ./pkg/storage -run '^TestS3CompatibleContract$' -count=1 -v
```

设置 `DRAARL_S3_TEST_CORS_ORIGIN` 后还会对预签名 PUT URL 发起浏览器等价的 `OPTIONS` 预检，并验证 Origin、PUT 和 `Content-Type`。只有使用无并发上传的专用测试桶时，
才可设置 `DRAARL_S3_TEST_DESTRUCTIVE_CLEANUP=true` 验证过期 staging 删除；默认
模式不会删除桶内其他 staging 对象。

R2 使用 `<account-id>.r2.cloudflarestorage.com`、`Region=auto`、`BucketLookup=path`，并启用 API 和预签名地址的 SSL。COS 使用 `cos.<region>.myqcloud.com`、真实 Region、包含 AppID 的 bucket 名和 `BucketLookup=dns`；OSS 使用 `oss-<region>.aliyuncs.com`、真实 Region 和 `BucketLookup=dns`。仓库不为存储契约保留常驻 GitHub Actions；此类测试使用专用测试环境按需手动执行，测试凭据不得写入仓库。GitHub Actions 只保留 Release 和 MkDocs Pages。

客户端资源的完整 HTTP 生命周期测试还需要名称以 `draarl_test_` 开头的专用
MySQL 数据库。它会先使用临时 local 目录，再在提供 `DRAARL_S3_TEST_*` 时使用
同一 S3 目标，覆盖 JWT 管理员鉴权、多目标直传、服务端 SHA-256、complete、
发布、manifest、按需签名下载、Range、ETag、撤回和固件隔离：

```bash
DRAARL_CLIENT_RESOURCE_E2E=true \
DRAARL_TEST_MYSQL_DSN='user:password@tcp(127.0.0.1:3306)/draarl_test_client_resource_http?charset=utf8mb4&parseTime=true&loc=Local' \
DRAARL_S3_TEST_PROVIDER=minio \
DRAARL_S3_TEST_ENDPOINT=127.0.0.1:9000 \
DRAARL_S3_TEST_PRESIGN_ENDPOINT=127.0.0.1:9000 \
DRAARL_S3_TEST_ACCESS_KEY=test-access-key \
DRAARL_S3_TEST_SECRET_KEY=test-secret-key \
DRAARL_S3_TEST_BUCKET=draarl-contract \
DRAARL_S3_TEST_BUCKET_LOOKUP=path \
go test ./internal/handler -run '^TestClientResourceHTTPE2E$' -count=1 -v
```

### 4.8 中心/边缘互联与 FRP

中心模式通过 `Interconnect` 开启 Type 0：TLS 控制面使用独立的
`ControlListen`（默认 `60100`），UDP 数据面复用 `System.Port`（默认
`60050`），不需要再开放一个 Type 0 UDP 端口。

边缘使用同一个二进制启动：

```bash
./draarl --edge -c config.yaml
```

边缘只读取最小 `Edge` 配置，不连接 MySQL、Redis、HTTP、存储、IPDB
或 APRS：

```yaml
Edge:
  Center: "center.example.com:60100"
  CenterUDP: "center.example.com:60050"
  Token: "后台生成的一次性注册凭据"
  Listen: ":60050"
  ProxyProtocol: ""
  TLSCAFile: "/etc/ssl/certs/center-ca.pem"
  TLSServerName: "center.example.com"
  IdentityFile: "edge-identity.json"
```

首次注册成功后，边缘会把中心签发的身份写入 `IdentityFile`；该文件等同
节点长期凭据，必须限制读取权限并纳入密钥备份/吊销流程。生产环境应验证
中心 TLS 证书，`InsecureSkipVerify` 只用于隔离的本地测试。

中心的 `Interconnect.CredentialRotationGraceSeconds` 控制在线轮换后的旧凭据
重连宽限期，默认 600 秒、最大 3600 秒。在线边缘会先持久化新 identity 再
确认轮换；离线轮换时，管理员必须把接口中仅显示一次的新凭据写入边缘配置
或 identity 文件。吊销凭据会立即断开节点并使当前、新旧宽限凭据全部失效。

`Interconnect.SessionRecoveryWindowSeconds` 控制中心重启或节点控制链断开后
保留旧设备入口证明的时间，默认 180 秒，可配置 30–600 秒。仍在运行且支持
会话重新确认的边缘会在新控制连接 ready 前批量证明设备、所有者、SSID、旧
NodeID 和旧控制会话。实体设备使用数据库入口证明；现代幽灵还必须提交随授权
续租轮换的短期 HMAC 恢复票据，中心验签后重新检查当前用户和频道权限。成功后
直接换取新短期会话，无需设备再次提交密码或 JWT。恢复期间转发保持 fail closed；
证明失败、设备或用户已失效、缺少幽灵恢复票据能力的旧版本边缘
以及超过窗口仍未认领的入口都会被清理，设备随后按普通流程重新认证。

`Edge.Listen` 是同一个双向 UDP socket 的本地地址，不只是接收过滤条件。
中心位于另一台主机时应使用 `:60050`、`0.0.0.0:60050` 或可到达的网卡
地址；绑定 `127.0.0.1` 会固定 Type 0 出站源地址，只适合同机测试。

Type 0 的 `SentAtMillis` 只执行 `±2s` 粗粒度安全新鲜度检查。下行包到达
边缘后，投影等待和队列帧龄使用本机单调时钟，默认 200ms，不会把跨地域
公网 RTT 或节点之间的墙上时钟偏差当成本地排队。详细格式见
[Type 0 节点互联协议](../节点互联协议.md)。

如果普通设备通过 FRP 进入边缘，在边缘配置中设置：

```yaml
Edge:
  ProxyProtocol: v2
```

这与中心直连接入使用的 `System.ProxyProtocol: v2` 作用相同，但配置项按
运行角色分开。DraARL 会保留两个地址：

- FRP 的 UDP 来源地址用于实际回包。
- PROXY v2 头中的客户端地址用于设备认证、限速、会话身份和来源记录。

未携带 PROXY v2 签名的 Type 0 中心数据包仍可在同一 UDP 端口正常处理。
启用 PROXY v2 后，必须通过防火墙、安全组或本机监听范围保证该 UDP 入口
只接受受信 FRP 实例的流量；PROXY 头本身不提供身份认证，直接暴露给任意
来源会允许伪造客户端 IP。

### 4.9 设备接入点发现

设备接入点发现在管理员后台的“站点配置 → 接入点”中管理，不再读取
`config.yaml`。发现服务始终开启，管理员可以调整凭证、健康状态和客户端缓存
时长；保存后立即生效，不需要重启服务。平台只返回入口列表；网络延迟由客户端
自行 ICMP 测量，不由服务器代测。

中心位于 NAT 或 FRP 后方时，“公网 UDP 地址”和“公网 UDP 端口”应填写设备
实际访问的外部地址和映射端口，而不是中心的内网监听地址。`System.Port` 仍是
中心实际监听端口，两者可以不同。

边缘入口的主机、端口、地区、昵称和是否发布由管理员在节点页维护。只有已注册、
启用、在线且心跳未过期的节点才会出现在列表中。列表不会返回内部 NodeID、TLS
控制地址、远端地址、凭据或运维指标。国内地区至少填写到市级；`Network` 是可选
的自定义识别标签，不参与平台测速或入口选择。中心入口未启用时不会再使用 APRS
的“本机地址”和“本机端口”作为兜底入口。

## 5. 后端运行

```bash
go mod download
go build -o draarl ./cmd/draarl
./draarl -c config.yaml
```

常用启动参数：

| 参数 | 说明 |
|---|---|
| `-c <path>` | 指定配置文件。 |
| `--edge` | 以无中心依赖的边缘模式启动；`--interconnect` 是兼容别名。 |
| `-v` | 打印版本信息。 |
| `-p json` | 打印关键配置。 |
| `-auto-migrate` | 显式创建或升级数据库结构；目标数据库完全没有表时，省略该参数也会自动初始化。 |
| `-reset-admin-pass <password>` | 重置管理员密码。 |
| `-migrate-storage <from:to>` | 跨存储驱动或 profile 迁移对象（如 `minio:local` 或 `minio-prod:r2-prod`），纯命令行，不启动主服务。 |
| `-migrate-dry-run` | 配合 `-migrate-storage`，仅统计迁移计划，不实际写入。 |
| `-migrate-delete-source` | 配合 `-migrate-storage`，迁移并校验成功后删除源端对象（默认保留）。 |

## 6. 存储引擎迁移

在不同存储引擎之间迁移文件对象（例如从 MinIO 迁到本地磁盘，或反向）。该命令为纯命令行工具，不启动主服务，也不修改数据库——因为数据库中保存的是 object key，两种引擎通用，迁移只是按 key 把对象从源端拷贝到目标端。

```bash
# 预览：只统计不写入
./draarl -c config.yaml -migrate-storage minio:local -migrate-dry-run

# 通过命名 profile 从 MinIO 迁移到 R2
./draarl -c config.yaml -migrate-storage minio-prod:r2-prod -migrate-dry-run

# 正式迁移（保留源端，便于验证）
./draarl -c config.yaml -migrate-storage minio:local

# 验证无误后，迁移并删除源端对象
./draarl -c config.yaml -migrate-storage minio:local -migrate-delete-source
```

要点：

- **源与目标从同一份配置读取**：`minio:local` 使用旧的 `Storage.MinIO` 与 `Storage.Local`；`minio-prod:r2-prod` 使用 `Storage.Profiles` 中两个独立 profile。迁移完成后，把 `Storage.ActiveProfile` 或 `Storage.Driver` 改成目标再启动服务。
- **仅支持跨引擎**：`local:local`、`minio:minio` 会被拒绝。同引擎换桶/换路径属高级场景，请用专用工具（如 `mc mirror`、`rsync`）。
- **断点续传**：目标端已存在同 key 且大小一致的对象会被跳过，因此进程意外退出后直接重跑即可，不会重复传输。写入为原子操作，崩溃不会残留半个对象。
- **非破坏**：默认只拷贝不删除源端。确认迁移结果无误后，再用 `-migrate-delete-source` 清理源端。
- **跳过范围**：`staging/`（未完成的临时上传）和 `frontend/`（CDN 同步产物）不迁移。
- **历史绝对 URL**：早期以完整 URL 存储的 logo/favicon 不在迁移范围内，如更换引擎后断链需重新上传。

## 7. 数据库迁移

当目标数据库完全没有表时，普通启动会自动执行 GORM 迁移并初始化表结构：

```bash
./draarl -c config.yaml
```

只要数据库中已经存在任意一张表，普通启动就不会修改数据库结构。创建缺失表、升级已有结构或清理遗留字段时，必须显式传入 `-auto-migrate`：

```bash
./draarl -c config.yaml -auto-migrate
```

群组自身呼号和设备准入白名单停用后，普通启动会直接忽略历史
`public_groups.call_sign`、`public_groups.allow_callsign_ssid` 列；显式执行
`-auto-migrate` 时会删除遗留列。表或列已经不存在时会安全跳过。
如果准入白名单列仍有非空配置，迁移会中止并要求先人工确认清理，避免静默丢失数据。

自动迁移会：

- 清理部分重复或孤儿数据。
- 自动创建/更新核心表结构。
- 建立级联外键约束。
- 确保 `users.callsign`、`devices(owner_id, ssid)` 等唯一索引。
- 删除 `group_members` 历史设备级字段。

生产环境首次升级前建议备份数据库。

从 `v1.1.4-alpha10` 升级到 `v1.1.5-alpha1` 的完整顺序、验证点和回滚方法见
[v1.1.5-alpha1 升级说明](11-v1.1.5-alpha1升级说明.md)。

## 8. 管理员初始化

首次启动时，如果数据库中不存在名为 `admin` 的用户，程序会创建默认管理员并在日志输出随机密码。该用户：

- 用户名：`admin`
- 角色：`admin`
- 审核状态：已通过

重置管理员密码：

```bash
./draarl -c config.yaml -reset-admin-pass "NewPassword123"
```

## 10. 发布构建

Unix/macOS/Linux：

```bash
./build.sh v1.2.3
```

Windows：

```powershell
.\build.bat v1.2.3
```

发布脚本流程：

1. 清理旧产物。
2. 构建 `www/dist`。
3. 将前端产物复制到 `internal/server/web/dist`。
4. 使用 `-tags=embed` 构建后端，将前端嵌入二进制。
5. 清理临时嵌入目录。

发布模式下，Go 二进制可同时提供 API 和前端页面。非 `embed` 构建只提供 API，访问前端路由会返回 `frontend not embedded, build with -tags=embed`。
