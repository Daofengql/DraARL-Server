## 本轮修复

### B3：Redis refresh 会话吊销的并发窗口

旧流程先读取用户会话集合，再批量写回吊销状态。用户在读取快照后登录或轮换时，新 token 可能不在这次吊销里，密码修改或 refresh token 重放会留下有效会话。

现在 `RevokeAllByUser` 监视用户索引，并在事务提交前监视快照中的 token hash；并发 `Create` / `Rotate` 修改索引会触发事务重试。`RevokeByTokenHash` 也改为 watch 事务，避免单 token 吊销覆盖并发轮换。刷新接口遇到并发失效会返回明确的 401，吊销传播失败返回 503，避免把服务端失败伪装成成功。

同时，用户索引 TTL 使用原子延长脚本，只在新过期时间更长时更新，短寿命 token 不会缩短长寿命会话的索引。

### B4：内存 refresh 存储的高频清理

开发 / 测试内存存储此前每次创建或查询都遍历全部会话做过期清理。现在维护扫描最多每分钟执行一次；授权仍由 token 的过期时间单独校验，清理节流不会延长会话有效期。

### B5：上传请求在 multipart 解析前缺少总量边界

头像、证书、站点品牌、固件和资源上传现在在解析表单前设置 `http.MaxBytesReader`，同时检查已知 `Content-Length`，超限返回 413。单文件大小校验仍保留；支持 multipart 和证书的 URL 编码直传字段。

## 前端黑夜模式

- 新增 `AppThemeProvider` / `useColorMode`，首次跟随操作系统偏好。
- 手动切换保存到 `localStorage`，其他标签页同步；公共头部提供带 tooltip 和 aria-label 的月亮 / 太阳按钮。
- 全局背景、卡片、抽屉、表格表头、导航选中态、统计图 tooltip 采用主题色；移除关键布局中的硬编码白色和不存在的 `primary.50` / `primary.100` 依赖。
- 实际检查了 1440×900、390×844、320×568 的登录、注册、用户管理和在线收发页面。黑夜模式刷新后保持，320px 头部仍能访问切换、登录和菜单；浏览器控制台无 error。

## 管理后台服务器概览

后台仪表盘新增管理员专用 `/api/system/overview` 接口和“服务器概览”区域，展示主机名、操作系统 / 架构、DraARL / Go 版本、运行时长、Goroutine、进程内存、GC 次数，以及 CPU、内存、磁盘使用率。接口不返回配置、环境变量、命令行参数或存储路径；CPU 首次采样没有基线时会显示“采集中”，避免误导。

页面每 15 秒自动刷新，也提供手动刷新按钮；移动端改为纵向资源卡片，实际检查了 1440×900 和 390×844，按钮与资源信息均可用。
