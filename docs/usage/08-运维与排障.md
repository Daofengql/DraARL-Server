# 08. 运维与排障

## 1. 常规检查清单

上线前建议确认：

- `config.yaml` 存在且路径正确。
- MySQL 可连接，数据库已创建，账号权限正确。
- `JWT.Secret` 长度至少 32 字符，或配置文件可被程序写回。
- `DeviceAuth.AESKey` 长度为 16、24 或 32 字节，或配置文件可被程序写回。
- Web 端口和 UDP 端口未被占用。
- `Web.FrontendURL` 和 `Web.AllowedOrigins` 与实际访问域名一致。
- 生产环境反向代理正确转发 WebSocket Upgrade。
- 当前 `Storage` 驱动（local 或 S3 兼容）按生产要求可写，Redis 按登录态持久化要求可用。

## 2. 服务无法启动

检查项：

- 配置文件路径是否正确。
- MySQL 地址、端口、账号、密码、数据库名是否正确。
- MySQL 用户是否有建表、改表、读写权限。
- release 构建必须确认 Redis 可连接；连接失败会阻止启动。development/test 构建才允许降级到内存存储。
- release 构建下是否配置了可解析的 `FrontendURL` 或 `AllowedOrigins`。
- 程序是否有权限写回 `config.yaml` 中自动生成的 JWT/AES 密钥。

## 3. 前端页面打不开

检查项：

- 是否使用 `-tags=embed` 构建了发布二进制。
- 如果是开发模式，Vite dev server 是否已启动。
- Vite 代理后端端口是否和 `config.yaml` 中的 `Web.Port` 一致。
- 浏览器来源是否在 `AllowedOrigins` 或 `FrontendURL` 中。
- 非 `embed` 构建只提供 API，访问前端路由会返回 `frontend not embedded, build with -tags=embed`。

## 4. 登录后接口 401

检查项：

- `localStorage.token` 是否存在。
- access token 是否过期。
- refresh token Cookie 是否存在。
- Redis 是否可用。
- development/test 构建若使用内存 refresh token 存储，服务重启后需要重新登录；release 构建不会采用该降级路径。
- 系统时间是否异常。

## 5. WebSocket 连接失败

检查项：

- 是否已经登录。
- 是否调用过 `/api/auth/ws-token/sync`。
- `ws_token` Cookie 是否被浏览器保存。
- `client_instance_id` 是否为稳定、非零 UUID，是否同时声明 `multi_receive_v1` 与 `source_group_v1`。
- 同账号是否已达到配置的幽灵在线 Session 上限。
- 页面 Origin 是否在白名单。
- 反向代理是否转发了 `Upgrade` 和 `Connection`。
- HTTPS 页面应使用 `wss://`。

## 6. 设备无法上线

检查项：

- UDP 端口是否开放。
- 用户名和设备密码是否正确。
- 用户是否审核通过。
- SSID 是否属于普通设备允许范围。
- 同一用户同一 SSID 是否已有设备在线。
- 如果是快速重连，心跳 DATA 扩展区 MAC 是否一致且格式为 `AA:BB:CC:DD:EE:FF`。
- 设备型号是否在协议允许范围内。

UDP 幽灵设备还需检查：Type 1 认证 JSON 是否包含 `version=1`、JWT、稳定 `client_instance_id` 和两项必需能力；认证成功后的心跳、文本与语音包是否在 Reserved 中回传 `session_tag`。UDP 地址/NAT 端口变化后必须重新认证。

## 7. 多收或来源频道异常

检查项：

- Session 是否同时声明 `multi_receive_v1` 和 `source_group_v1`；缺少任一能力会直接认证失败。
- `/api/radio/sessions` 中 `tx_group_id`、`rx_group_ids` 是否符合预期，发送频道是否包含在接收集合中。
- 私有群组成员资格、群组启用状态和互联拓扑是否仍有效；权限变更会自动清理路由或断开无法恢复的 Session。
- UDP/WS 下行 Type 4/5 的 Reserved 是否被客户端按大端 `uint32 source_group_id` 解析。
- 边缘与中心是否同时协商 `ghost_multi_session`（功能位 8）和 `ghost_recovery_ticket`（功能位 9）；缺少任一能力的旧边缘不承载幽灵 Session。
- Web 混音器中目标频道是否已开启、音量是否为零。

## 8. 幽灵 Session 运维

- 后台 `/admin/radio-sessions` 查看实时 Session 摘要；列表不会显示完整实例 ID、tag 或网络端点。
- 精确断开前核对账号、平台、连接方式、发送频道和接收集合，操作只影响所选 Session。
- `/api/udp/metrics` 的 `ghost_sessions` 检查在线数、订阅量和上限拒绝。
- `ghost_packets` 持续增长通常表示旧 tag、伪造身份、NAT 端点变化后未重新认证或运行时状态不同步。
- `receiver_cache.deduplicated` 与 `websocket.fanout_deduplicated` 表示多订阅/互联路径去重；应结合候选数和最终发送数判断。
- `message_api` 的累计耗时桶用于计算分位；重点关注 `responses_5xx`、`query_errors`、`cursor_rejects` 和 `audio_url_failures`。
- 应用日志中的幽灵 `session` 只显示八字符短 ID；完整 Session 仅在受控 API 响应和协议应答中使用。

## 9. 设备配置无法同步

检查项：

- 设备是否在线。
- 当前用户是否拥有该设备，或是否为管理员接口。
- 配置值是否在允许范围内。
- `power_level` 是否使用当前支持值，历史值 `2` 会兼容映射为高功率。
- `rx_tone_mode` / `tx_tone_mode` 是否为 `off`、`ctcss`、`cdcss_n`、`cdcss_i`。

## 10. 上传失败

检查项：

- 当前 `Storage.Driver` / `ActiveProfile` 是否指向预期存储。
- local 的 `RootPath` 是否可写；S3 兼容服务是否可连接，Bucket 是否存在，服务账号是否有读写权限。
- `PresignEndpoint`（旧 MinIO 配置为 `PublicEndpoint`）是否是浏览器可访问的 S3 API 地址；如配置 `DownloadURLPrefix`，代理是否恢复了签名 Host、路径并完整透传查询参数。
- 文件大小和类型是否满足接口限制。
- 反向代理上传大小限制是否过小。

## 11. 邮箱验证码无法发送

检查项：

- SMTP Host、Port、SSL 是否正确。
- `sender_email` 是否与授权码匹配。
- 邮箱供应商是否要求 SMTP 授权码而不是登录密码。
- 注册设置是否要求邮箱验证。
- 图片验证码是否过期。

## 12. 通信记录没有音频

检查项：

- 站点配置中是否启用音频记录。
- 当前对象存储驱动是否可用。
- 最小录制阈值是否过高。
- 最大录制时长是否导致通信被提前断开。
- 批量上传间隔是否配置合理。

## 13. 建议的备份对象

生产环境建议定期备份：

- MySQL 数据库。
- local 存储目录或 S3 兼容 Bucket。
- 每台边缘的 `edge-identity.json`（等同节点长期凭据）。
- `config.yaml`。
- `ipinfo.ipdb`，如使用自定义 IP 地址库。
- 发布二进制和版本号。

## 15. 健康检查、指标和追踪

`/healthz` 表示进程存活；`/readyz` 并发在 2 秒预算内检查 MySQL/Redis，依赖异常返回 503 和 ok/unavailable 状态，不返回凭据或地址。ready 不代表对象存储、APRS 或外部 SSO 全部正常，仍需对应功能探测。重启前先定位故障，避免反复启动放大数据库压力。

`/metrics` 是 Prometheus 文本格式，要求有效管理员 Bearer access token。采集器通过受限权限的 credentials_file 提供短期令牌，并在过期前更新，401 不应被误判为业务故障。不要在公开网关暴露采集令牌。指标包括 devices_online、udp_packets_total/dropped_total、websocket_connections、cache_hits_total/misses_total、db_query_duration_seconds_sum/count、db_errors_total、两个数据库池及 HTTP 路由计数/耗时。HTTP 路由使用模板而非实际设备 ID，未知 method 归 OTHER，防止标签无限增长。

告警应先采样设定站点基线：ready 持续失败、5xx 比例上升、UDP dropped 的增长率异常、online_events_dropped 持续增长、池等待与查询平均耗时上升。平均耗时用 rate(duration_sum)/rate(duration_count)，当前 HTTP/DB 指标不提供分位数直方图，不能据此计算 p95。在线数下降也可能是计划维护，需要与入口日志和设备心跳一起判断。

配置 Observability.LogFormat=json 后输出 UTC timestamp、level、message，HTTP 带 trace_id、user_id、路由/耗时，WS/认证记录按字段输出；保留的 legacy 日志作为 message 进入统一处理器，尚非所有子系统都具备相同字段。不要开启会输出 SQL 参数或密钥的调试日志。

开启 TracingEnabled 并设置 OTLPEndpoint 为 OTLP/HTTP 收集器的绝对 URL，未写路径默认 `/v1/traces`，自定义路径保留。TraceSampleRatio 默认 0.01；本地测试可用 1，生产按流量调整。HTTP 支持 traceparent，响应 X-Trace-ID 可关联数据库子 span；GORM 导出操作/表和耗时，不含 SQL 参数。UDP 是独立处理 span，协议未携带跨节点 traceparent，不能声称已建立完整跨中心音频因果链。批队列 2048、导出超时 3 秒，收集器离线时不无限阻塞业务；日志可能记录导出失败。

## 16. 常见故障与恢复顺序

- Error 1452 / fk_devices_group：未分组设备应存 NULL，不能依靠插入 ID=0 或关闭外键。使用新版本重试注册，核对用户默认群组是否引用已删除 ID。默认群组不是设备上线的必需条件。
- 列表短时显示旧在线状态：先看事件同步/丢弃计数及 10 秒全量校准，再查数据库、缓存和在线会话。不要直接修改进程内索引。
- 音频处理在 Linux 下输出结果后仍空转：检查 ffmpeg/ffprobe 版本和限制；新版本在子进程固定 BLAS/OpenMP 单线程，保留原有 CPU/内存上限。使用真实转码 E2E 复现，不应通过取消限制来绕过问题。
- 慢请求：按 trace_id 找 HTTP 与数据库操作，结合池等待、慢查询和队列指标；区分数据库压力、外部依赖超时和高频无效请求。
- 迁移失败：停止重复写入和多实例启动，保留数据库副本，查 running/completed 与具体失败步骤，修复后重试。不要手动把 running 改 completed。

紧急恢复先隔离故障入口，停止写入，保存日志和备份，再按 [迁移与回退](../database-migrations.md) 恢复到新库验证。需要旧版程序时同时恢复其配套配置、密钥和存储快照，确认后切流量。
