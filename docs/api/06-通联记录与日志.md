# 06. 通联记录与日志

## 1. 通信记录 Comm Records（JWT）

通信记录用于“本人设备发信记录”和管理员审计，不等同于频道聊天历史。普通用户的列表和详情只允许访问本人实体设备或本人幽灵设备产生的记录；管理员只有显式使用后台模式时读取全局记录。音频签名 URL 仅在记录级授权通过后生成。

### `GET /api/comm-records`

参数：

- `page`
- `page_size`
- `device_id`
- `group_id`
- `user_id`（仅管理员全局模式）
- `admin_mode=true`（管理员后台查看全局）

返回示例：

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "list": [
      {
        "id": 10001,
        "device_id": 123,
        "device_name": "BG7XXX-11",
        "dev_model": 107,
        "group_id": 1001,
        "group_name": "深圳应急群",
        "start_time": "2026-04-05 14:22:01",
        "end_time": "2026-04-05 14:22:06",
        "duration_ms": 5000,
        "msg_type": 0,
        "audio_url": "https://.../xxx.opus"
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 20
  }
}
```

### `GET /api/comm-records/:id`

普通用户跨账号按 ID 访问返回 `403`。需要查看频道中其他发送者的消息时，必须使用下述频道消息 API，不能依靠枚举通信记录 ID。

## 2. 频道消息历史（JWT + Approved）

频道消息与通信记录来源于同一张 `comm_records` 表，但查询边界、授权和响应模型独立。消息接口按群组 ACL 返回频道内所有可见发送者的已完成消息，不按当前用户设备过滤。

### `GET /api/groups/:id/messages`

参数：

- `limit`：范围由 `MessageAPI.MaxPageSize` 配置，默认 `1-100`；缺省值由 `MessageAPI.DefaultPageSize` 配置，默认 `50`。
- `cursor`：上一页的 `next_cursor`，不透明字符串。
- `message_type`：`all`、`voice` 或 `text`，默认 `all`。

```json
{
  "code": 200,
  "data": {
    "messages": [
      {
        "id": 10001,
        "message_type": "voice",
        "source_group_id": 1002,
        "source_group_name": "互联来源群组",
        "requested_group_id": 1001,
        "sender": {
          "user_id": 12,
          "username": "radio-user",
          "callsign": "BG7XXX",
          "nickname": "Operator",
          "ssid": 101,
          "dev_model": 101,
          "is_ghost": true
        },
        "sent_at": "2026-08-05T12:00:00Z",
        "end_time": "2026-08-05T12:00:03Z",
        "duration_ms": 3000,
        "audio_url": "https://storage.example/authorized.opus?...",
        "audio_size": 20480,
        "audio_format": "draarl-opus-raw",
        "status": 2
      }
    ],
    "next_cursor": "eyJzdGFydF90aW1lIjoiLi4uIiwiaWQiOjEwMDAxfQ",
    "has_more": true,
    "server_time": "2026-08-05T12:01:00Z"
  }
}
```

文本消息使用 `text_content`，不返回音频字段。列表只返回 `status=2` 的完整记录。发送者优先使用消息写入时的快照，因此用户改名、设备删除或转让不会改写历史身份。

游标按 `(start_time, id)` 降序。服务端对每个可见源群组执行有界复合索引查询，再合并互联群组结果；并发插入的新消息不会混入使用旧游标请求的下一页。

### `GET /api/groups/:id/messages/:message_id`

返回一条频道消息。请求群组先通过 ACL，再验证消息属于该群组当前可见的互联范围；无权限时返回 `403`，不属于范围或不存在时返回 `404`。语音签名 URL 只在以上检查全部通过后生成。

列表和详情共享部署级查询保护：账号/IP 固定一分钟窗口超限分别返回 `429 message_api_user_rate_limited` 或 `429 message_api_ip_rate_limited`，并携带 `Retry-After`；并发查询槽满返回 `503 message_api_busy` 和 `Retry-After: 1`。客户端应按响应等待，不应立即循环重试。

### 权限与互联语义

- 公开群组允许已审核用户查看。
- 私有群组只允许管理员、群主或已验证成员查看；成员退出或被移除后立即失去列表和详情权限。
- 禁用、虚拟或不存在的请求群组不可查询。
- 第一版按“当前启用的互联拓扑”计算可见源群组，同一消息经多条互联路径只返回一次。
- `requested_group_id` 是客户端请求的频道，`source_group_id` 是消息实际发送频道，两者不能互换。
- `/api/comm-records?group_id=...` 仅在旧客户端迁移期保留兼容行为，新客户端不得把它作为聊天历史接口。

### 数据库迁移与查询索引

显式执行 `-auto-migrate` 会增加 `message_type`、`text_content`、发送者快照字段，以及复合索引 `idx_comm_records_group_status_start_id(group_id,status,start_time,id)` 和 `idx_comm_records_group_status_type_start_id(group_id,status,message_type,start_time,id)`。前者服务无类型过滤的频道游标，后者避免类型过滤在稀疏频道中扫描大量不匹配记录。迁移会分批处理旧 `audio_path='text:...'` 数据；旧服务端会忽略新增字段，回滚服务端时不得删除这些列或索引。

百万行验收使用 `DRAARL_MESSAGE_PERFORMANCE_E2E=true`。当前 MySQL 8.4 基线中，无类型过滤的四个互联群组从 1,000,000 行中合并取 50 条约 23 ms；类型过滤在新增索引前约 4.08 s，增加索引后约 10 ms。完整方法与结果见[幽灵多收与消息查询性能验证](../幽灵多收与消息查询性能验证.md)；发布环境仍需执行自己的 `EXPLAIN ANALYZE`。

## 5. 通联日志 Logbook（JWT）

### 用户接口

- `GET /api/logbooks`
- `GET /api/logbooks/:id`
- `POST /api/logbooks`
- `PUT /api/logbooks/:id`
- `DELETE /api/logbooks/:id`
- `DELETE /api/logbooks/batch`

创建请求示例：

```json
{
  "my_callsign": "BG7XXX",
  "time_utc": "2026-04-05 06:35:20",
  "tx_frequency": 439.5000,
  "rx_frequency": 439.5000,
  "mode": "FM",
  "callsign": "BG7YYY",
  "their_rst": "59",
  "my_rst": "59",
  "notes": "首次通联"
}
```

批量删除请求：

```json
{ "ids": [101, 102, 103] }
```

### 管理员接口（Admin）

- `GET /api/admin/logbooks`
- `GET /api/admin/logbooks/:id`
- `PUT /api/admin/logbooks/:id`
- `DELETE /api/admin/logbooks/:id`
- `DELETE /api/admin/logbooks/batch`

- `GET /api/user/radio-presets`

- `DELETE /api/user/radio-presets/:id`
- `PUT /api/user/radio-presets/reorder`

```json
{
  "name": "车载台",

  "qth": "Shenzhen",
```

```json
{ "orders": [{ "id": 1, "order": 1 }, { "id": 2, "order": 2 }] }
```
